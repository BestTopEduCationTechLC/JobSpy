JobSpy Search — Error Code Reference (DRAFT)
==============================================

STATUS: This is a planning document only. Per the revision request that
created it, NONE of these codes are wired into the code yet — no function
currently throws, logs, or displays any of these. This file exists purely
so the codes can be reviewed before any implementation work begins.

Format: 4-digit hexadecimal, uppercase, written as a bare code (e.g. 1000).
The first hex digit groups codes by the area of the app that would raise
them; the repo was scanned end-to-end (docs/assets/app.js, every scraper/*.py
script, the trigger-scrape Supabase Edge Function, and the three GitHub
Actions workflows) to build this list, one code per function/workflow step
that has a plausible failure case.

Range map
---------
1000-1FFF  Auth (docs/assets/app.js)
2000-2FFF  Saved jobs (docs/assets/app.js)
3000-3FFF  One-off search runs (docs/assets/app.js)
4000-4FFF  Scheduled searches (docs/assets/app.js)
5000-5FFF  Search parsing / PDF export (docs/assets/app.js)
6000-6FFF  Navigation / shared UI (docs/assets/app.js)
7000-7FFF  Backend scraper scripts (scraper/*.py)
8000-8FFF  trigger-scrape Edge Function (supabase/functions/trigger-scrape)
9000-9FFF  GitHub Actions workflows (.github/workflows/*.yml)


1000-1FFF — Auth (docs/assets/app.js)
--------------------------------------
1000  getUser() — supabase.auth.getSession() failed (network/Supabase outage).
1001  sessionToUser() — session.user missing expected shape (malformed session object).
1002  normalizeUsername() — non-string input coerced unexpectedly (defensive; input wasn't a string/undefined).
1003  validateUsername() — username fails USERNAME_RE (bad length or disallowed characters).
1004  validatePassword() — password shorter than the 6-character minimum.
1005  signUp() — supabase.auth.signUp() returned an error (Supabase/network failure).
1006  signUp() — email already registered (data.user.identities.length === 0, the silent-duplicate case).
1007  signUp() — email failed EMAIL_RE validation.
1008  signIn() — get_login_email RPC call itself errored (RPC not deployed / not granted to anon).
1009  signIn() — get_login_email RPC returned null (no account for that username).
100A  signIn() — supabase.auth.signInWithPassword() returned "Invalid login credentials".
100B  signIn() — supabase.auth.signInWithPassword() returned an unconfirmed-email error.
100C  requestPasswordReset() — supabase.auth.resetPasswordForEmail() returned an error.
100D  updatePassword() — supabase.auth.updateUser({password}) returned an error.
100E  getEmailStatus() — supabase.auth.getUser() failed while reading current/pending email.
100F  updateContactEmail() — new address failed EMAIL_RE validation.
1010  updateContactEmail() — supabase.auth.updateUser({email}) returned an error.

Notes for whoever implements this later
----------------------------------------
- These are proposed, not final — several ranges (1xxx and 7xxx especially)
  have room for the more specific sub-cases already known from real incidents
  (e.g. the country_indeed "" vs None vs valid-string distinction under 7008).
- Recommend surfacing the code alongside the existing human-readable message
  rather than replacing it (e.g. "[7008] Search failed: Invalid country
  string: ''"), and logging it into the existing error_logs-style pattern if
  that feature is reintroduced.
- No code here should be treated as stable/frozen until implementation
  actually begins — this file is the "what could this even mean" draft asked
  for, not a spec.
